## 🚨 **발견된 문제**

### **증상**
```
WARN Moving @eslint/eslintrc that was installed by a different package manager
WARN 53 other warnings
```

### **원인**
- ❌ npm과 pnpm을 혼용하여 설치
- ❌ package-lock.json과 pnpm-lock.yaml이 동시 존재
- ❌ node_modules 불일치

### **결과**
- 패키지 충돌
- 버전 불일치
- 예상치 못한 동작

---

## ✅ **해결 원칙**

### **1. pnpm만 사용** (프로젝트 표준)

```bash
# ✅ 올바름
pnpm install
pnpm add package-name
pnpm remove package-name

# ❌ 금지
npm install
npm install package-name
npm uninstall package-name
```

### **2. Lock 파일 관리**

**유지해야 할 파일:**
- ✅ `pnpm-lock.yaml` (pnpm 전용)
- ✅ `pnpm-workspace.yaml` (monorepo 설정)

**삭제해야 할 파일:**
- ❌ `package-lock.json` (npm 전용)
- ❌ `yarn.lock` (yarn 전용)

## 🔧 **문제 해결 방법**

### **Option 1: 클린 설치** (추천!)

```batch
# 모든 node_modules 삭제 후 pnpm으로 재설치
clean-install.bat
```

**자동으로 처리:**
1. server/node_modules 삭제
2. client/node_modules 삭제
3. package-lock.json 삭제 (npm 흔적 제거)
4. pnpm으로 전체 재설치

### **Option 2: 수동 정리**

```bash
# 1. 모든 node_modules 삭제
rd /s /q server\node_modules
rd /s /q client\node_modules
rd /s /q node_modules

# 2. npm lock 파일 삭제
del server\package-lock.json
del client\package-lock.json
del package-lock.json

# 3. pnpm으로 재설치
cd server && pnpm install && cd ..
cd client && pnpm install && cd ..
```

### **Option 3: 캐시 정리**

```bash
# pnpm 캐시 정리
pnpm store prune

# 전체 재설치
pnpm install --force
```

### **왜 이제야 설치되었나?**

**가능한 시나리오:**

1. **이전에 npm으로 부분 설치**
   - 일부만 설치되었거나
   - 버전이 맞지 않았음

2. **package.json 업데이트 후 재설치 안 함**
   - 새 패키지 추가했는데
   - `pnpm install` 안 했음

3. **lock 파일 불일치**
   - pnpm-lock.yaml은 최신
   - node_modules는 구버전
