## 🎯 프로젝트 개요

JJ Swim Lab은 수영 교육을 위한 AI 기반 학습 플랫폼입니다. TensorFlow.js와 MediaPipe를 활용한 실시간 자세 분석, 개인화된 학습 계획, 그리고 종합적인 교육 관리 시스템을 제공합니다.

### 🏊‍♂️ 주요 기능
- **AI 기반 자세 분석** - 실시간 자세 인식 및 피드백
- **개인화된 학습 계획** - 사용자 수준에 맞는 맞춤형 커리큘럼
- **진도 추적** - 학습 진행 상황 모니터링
- **강사 대시보드** - 학생 관리 및 진도 추적
- **센터 관리** - 수영장별 운영 관리

## 🚨 문제 해결 가이드

### ⚠️ 컴파일러 오류의 특성

**중요**: TypeScript 컴파일 오류는 **빌드 과정에서만 발견**됩니다. 코드 편집기에서는 미리 감지할 수 없습니다.

#### 🔍 오류 발견 시점
- **빌드 전**: ❌ 오류를 미리 알 수 없음
- **빌드 중**: ✅ `npm run build` 실행 시 발견
- **빌드 후**: ✅ 오류 해결 후 재빌드로 확인

### 🛠️ 자주 발생하는 오류 패턴과 예방법

#### 1. 의존성 버전 호환성 문제

##### ❌ Faker.js 오래된 API (더 이상 지원되지 않음)
```typescript
// 이전 버전 (지원 중단)
faker.setLocale('ko')           // ❌ setLocale 메서드 없음
faker.locale = 'ko'             // ❌ locale 속성 없음
faker.internet.userName()       // ❌ userName → username으로 변경
faker.datatype.boolean(0.9)     // ❌ 파라미터 지원 중단
faker.phone.number('010-####-####') // ❌ 형식 지정 불가
faker.number.float({ precision: 0.1 }) // ❌ precision → fractionDigits로 변경
```

##### ✅ 최신 Faker.js API
```typescript
// 최신 버전 (권장)
// 로케일 설정 제거 (기본 영어 사용)
faker.internet.username()       // ✅ username으로 변경
faker.datatype.boolean()        // ✅ 파라미터 없음
faker.phone.number()            // ✅ 자동 형식 생성
faker.number.float({ fractionDigits: 1 }) // ✅ fractionDigits 사용
```

#### 2. React/Next.js 컴포넌트 Import 오류

##### ❌ 잘못된 Import 방식
```typescript
// 잘못된 예시
import { Button } from './ui/Button'     // ❌ Button은 default export
import { Input } from './ui/Input'       // ❌ Input은 default export
import Progress from './ui/Progress'      // ❌ Progress는 named export
import { Card } from './ui/card'         // ❌ Card는 default export
```

##### ✅ 올바른 Import 방식
```typescript
// 올바른 예시
import Button from './ui/Button'         // ✅ default export
import Input from './ui/Input'           // ✅ default export
import { Progress } from './ui/Progress' // ✅ named export
import Card, { CardContent, CardHeader, CardTitle } from './ui/Card' // ✅ default + named
```

#### 3. 타입 정의 불일치

##### ❌ 타입 불일치 예시
```typescript
// 잘못된 예시
interface HealthProfile {
  bloodType: string;           // ❌ 너무 광범위한 타입
  activityLevel: string;       // ❌ 너무 광범위한 타입
}

// 사용 시
const profile: HealthProfile = {
  bloodType: "A+",            // ❌ 타입 오류
  activityLevel: "moderately_active" // ❌ 타입 오류
}
```

##### ✅ 올바른 타입 정의
```typescript
// 올바른 예시
interface HealthProfile {
  bloodType: "A+" | "A-" | "B+" | "B-" | "AB+" | "AB-" | "O+" | "O-";
  activityLevel: "sedentary" | "lightly_active" | "moderately_active" | "very_active" | "extremely_active";
}

// 사용 시
const profile: HealthProfile = {
  bloodType: "A+",            // ✅ 타입 일치
  activityLevel: "moderately_active" // ✅ 타입 일치
}
```

- **개발 환경 표준화** (Docker, IDE 설정)
- **코드 품질 모니터링 시스템 구축**

### 3. 장기 목표 (3-6개월)
- **마이크로프론트엔드 아키텍처 검토**
- **서버 사이드 렌더링 최적화**
- **국제화(i18n) 지원 확장**

### 🚀 향후 개선 방향

#### 1. 자동화 도구 도입
- **Pre-commit hooks**: 커밋 전 자동 검사
- **CI/CD 파이프라인**: 자동 빌드 및 테스트
- **의존성 모니터링**: 보안 취약점 자동 감지

#### 2. 개발 환경 표준화
- **Docker 컨테이너**: 일관된 개발 환경
- **IDE 설정 공유**: 팀원 간 동일한 개발 환경
- **코드 스타일 가이드**: 일관된 코드 작성 규칙

#### 3. 지속적 학습
- **의존성 변경사항 추적**: 주요 라이브러리 업데이트 모니터링
- **커뮤니티 참여**: 개발자 커뮤니티에서 최신 정보 습득
- **정기적인 코드 리뷰**: 팀원 간 코드 품질 개선
