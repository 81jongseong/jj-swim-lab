# 🌿 JJ Swim Lab - 브랜치 관리 전략

## 📋 브랜치 구조

### 메인 브랜치
- **`main`**: 프로덕션 배포용 안정 버전
- **`develop`**: 개발 통합 브랜치
- **`glb-debug-viewer`**: 현재 개발 브랜치 (3D 뷰어 디버깅)

### 작업 브랜치
- **`server`**: 서버 전용 작업 브랜치
- **`fix-navigation-menu`**: 네비게이션 메뉴 수정 브랜치

## 🔄 브랜치 전략

### 1. 개발 브랜치 (`glb-debug-viewer`)
- **용도**: 현재 활발히 개발 중인 기능
- **작업 방식**: 
  - 기능 개발 완료 후 `main` 또는 `develop`으로 병합
  - 정기적으로 `main`에서 최신 변경사항 가져오기

### 2. 메인 브랜치 (`main`)
- **용도**: 프로덕션 배포용
- **보호 규칙**: 
  - 직접 푸시 금지 (Pull Request 필수)
  - 코드 리뷰 후 병합

### 3. 개발 통합 브랜치 (`develop`)
- **용도**: 여러 기능 통합 테스트
- **작업 방식**: 
  - 기능 브랜치에서 병합
  - 테스트 완료 후 `main`으로 병합

## 📝 브랜치 작업 가이드

### 새 브랜치 생성
```bash
# 메인 브랜치에서 최신 변경사항 가져오기
git checkout main
git pull origin main

# 새 브랜치 생성 및 전환
git checkout -b feature/새기능명

# 작업 후 푸시
git push origin feature/새기능명
```

### 브랜치 병합
```bash
# 작업 브랜치에서 메인으로 병합
git checkout main
git pull origin main
git merge feature/새기능명
git push origin main
```

### 브랜치 삭제
```bash
# 로컬 브랜치 삭제
git branch -d feature/새기능명

# 원격 브랜치 삭제
git push origin --delete feature/새기능명
```

## 🔍 현재 브랜치 확인

### 로컬 브랜치 목록
```bash
git branch
```

### 원격 브랜치 목록
```bash
git branch -r
```

### 모든 브랜치 목록
```bash
git branch -a
```

## ⚠️ 주의사항

1. **메인 브랜치 보호**: `main` 브랜치는 직접 푸시하지 않기
2. **정기 동기화**: 작업 브랜치는 주기적으로 `main`에서 최신 변경사항 가져오기
3. **브랜치 정리**: 병합 완료된 브랜치는 삭제하여 정리
4. **커밋 메시지**: 명확한 커밋 메시지 작성 (한글 가능)
