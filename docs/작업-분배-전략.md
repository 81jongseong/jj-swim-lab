# 👥 JJ Swim Lab - 작업 분배 전략

> **목적**: 유지보수 작업을 효율적으로 분배하여 진행  
> **원칙**: 작업 특성에 따라 적절한 담당자 배정

---

## 🎯 **작업 분배 원칙**

### **혼자 진행 (Auto)**
- 전체 코드베이스 이해가 필요한 작업
- 일관성과 통일성이 중요한 작업
- 아키텍처 변경이 필요한 작업

### **나눠서 진행 (Auto + 노트북)**
- 독립적으로 진행 가능한 작업
- 파일별로 분리 가능한 작업
- 병렬 처리로 속도 향상 가능한 작업

---

## 📋 **작업별 분배 전략**

### 1. **TODO 주석 정리** → **혼자 진행 (Auto)**
- **이유**: 
  - 전체 코드베이스 구조 이해 필요
  - TODO 간 의존성 파악 필요
  - 우선순위 결정 시 전체 맥락 필요
- **작업 방식**:
  - Auto가 전체 TODO 목록 작성
  - 우선순위별 분류
  - 이슈 트래커로 이동

---

### 2. **보안 점검** → **나눠서 진행**
- **Auto 담당**: 
  - `npm audit` 실행 및 분석
  - 서버 보안 취약점 수정
  - 인증/인가 로직 검토
- **노트북 담당**:
  - Client 보안 취약점 수정
  - 환경 변수 보안 검토
  - CORS 설정 확인

---

### 3. **코드 품질 개선** → **나눠서 진행**
- **Auto 담당**:
  - Server 코드 리팩토링
  - Server console.log → logger 교체
  - Server 중복 코드 제거
- **노트북 담당**:
  - Client 코드 리팩토링
  - Client console.log → logger 교체
  - Client 중복 코드 제거

**작업 분할 방법**:
```bash
# Auto: Server 작업
cd server
# console.log 찾기 및 교체

# 노트북: Client 작업  
cd client
# console.log 찾기 및 교체
```

---

### 4. **문서화 개선** → **나눠서 진행**
- **Auto 담당**:
  - Server 파일 주석 보완
  - Server API 문서 작성
  - Server 함수 JSDoc 추가
- **노트북 담당**:
  - Client 파일 주석 보완
  - Client 컴포넌트 문서 작성
  - Client 함수 JSDoc 추가

**작업 분할 방법**:
- 파일 경로 기준: `server/` → Auto, `client/` → 노트북
- 또는 기능별: 퀴즈 관련 → 노트북, 기타 → Auto

---

### 5. **성능 최적화** → **나눠서 진행**
- **Auto 담당**:
  - Server API 응답 시간 개선
  - 데이터베이스 쿼리 최적화
  - Server 캐싱 전략
- **노트북 담당**:
  - Client 번들 크기 최적화
  - 이미지 최적화 (WebP 변환)
  - Client 렌더링 성능 개선

---

### 6. **테스트 커버리지** → **나눠서 진행**
- **Auto 담당**:
  - Server 단위 테스트
  - Server API 통합 테스트
- **노트북 담당**:
  - Client 컴포넌트 테스트
  - Client E2E 테스트
  - canvas 모듈 오류 해결 (선택사항)

---

## 🔄 **작업 진행 방식**

### **방식 1: 순차 진행 (권장)**
1. Auto가 작업 목록 및 가이드 작성
2. 노트북이 독립적인 작업 시작
3. Auto가 전체적인 작업 진행
4. 주기적으로 동기화 및 검토

### **방식 2: 병렬 진행**
1. 작업을 명확히 분리 (Server/Client)
2. 동시에 진행
3. 주기적으로 동기화
4. 충돌 방지를 위해 파일 경로 기준 분리

## 📝 **작업 분배 예시**

### **시나리오 1: 보안 점검**
```
Auto (데스크탑):
- npm audit 실행
- server/ 보안 취약점 수정
- 인증 로직 검토

노트북:
- client/ 보안 취약점 수정
- 환경 변수 검토
- CORS 설정 확인
```

### **시나리오 2: 코드 품질 개선**
```
Auto (데스크탑):
- server/src/routes/ console.log → logger
- server/src/services/ 리팩토링
- server/ 중복 코드 제거

노트북:
- client/app/ console.log → logger
- client/components/ 리팩토링
- client/ 중복 코드 제거
```

### **시나리오 3: 문서화 개선**
```
Auto (데스크탑):
- server/src/routes/quiz.ts 주석 보완
- server/src/models/Quiz.ts 문서화
- server API 문서 업데이트

노트북:
- client/app/admin/quiz/ 주석 보완
- client/components/ 문서화
- client 사용 가이드 작성
```

## ⚠️ **주의사항**

### **충돌 방지**
1. **파일 경로 기준 분리**: `server/` → Auto, `client/` → 노트북
2. **기능별 분리**: 퀴즈 관련 → 노트북, 기타 → Auto
3. **주기적 동기화**: 작업 전 `git pull` 필수

### **일관성 유지**
1. **코딩 스타일**: 기존 스타일 가이드 준수
2. **커밋 메시지**: 명확한 메시지 작성
3. **문서 형식**: 기존 문서 형식 유지

```bash
# 작업 완료 후 동기화
git pull origin glb-debug-viewer
git push origin glb-debug-viewer
```
