## 🎯 **핵심 원칙**

### 1. **`as any` 사용 최소화**

```typescript
// ❌ 나쁜 예: as any 남발
const data = (response as any).data.users;
const css = (config as any).settings.css;

// ✅ 좋은 예: 명확한 타입 정의
interface ApiUsersResponse {
  data: {
    users: User[];
    total: number;
  };
}
const response = await apiClient.get<ApiUsersResponse>('/api/users');
const users = response.data.users; // 타입 안전!
```

**허용되는 경우만 `as any` 사용:**
- 외부 라이브러리 타입 문제 (임시)
- 레거시 코드 마이그레이션 중
- 복잡한 제네릭 타입 변환

---

### 2. **타입 정의는 기능과 함께 업데이트**

```typescript
// ❌ 나쁜 예: 기능만 추가, 타입은 방치
interface SavedProgram {
  id: string;
  name: string;
  // ... 나중에 58개 속성 추가했지만 타입은 업데이트 안 함!
}

// ✅ 좋은 예: 기능 추가 시 타입도 즉시 업데이트
interface SavedProgram {
  id: string;
  name: string;
  // 새 기능 추가할 때 타입도 함께 추가!
  sessionDuration?: number;  // 2025-10-15 추가
  mainStrokes?: string[];    // 2025-10-18 추가
  excludedStrokes?: string[]; // 2025-10-18 추가
}
```

**룰:**
- 새 속성 추가 → 즉시 타입 정의 업데이트
- API 변경 → 응답 타입 즉시 업데이트
- 컴포넌트 props 추가 → 인터페이스 즉시 업데이트

## 🚫 **금지 패턴**

### 1. **무분별한 `as any` 사용**

```typescript
// ❌ 절대 금지
const data = (response as any).whatever;

// ✅ 대신 이렇게
interface ResponseType {
  whatever: string;
}
const response = await apiClient.get<ResponseType>('/api/endpoint');
const data = response.data.whatever;
```

### 2. **타입 없는 함수 파라미터**

```typescript
// ❌ 금지
function updateUser(data) {
  // data가 뭔지 모름!
}

// ✅ 필수
function updateUser(data: { 
  name: string; 
  email: string; 
  age?: number;
}) {
  // data 타입이 명확!
}
```

### 3. **인터페이스와 타입의 불일치**

```typescript
// ❌ 금지: 실제 데이터와 타입이 다름
interface User {
  name: string;
}

// 실제로는 membershipTier도 사용하는데 타입 정의는 없음!
const tier = user.membershipTier; // 오류!

// ✅ 필수: 실제 사용하는 모든 속성 정의
interface User {
  name: string;
  membershipTier?: string; // 실제 사용하는 속성 모두 정의!
}
```

### 4. **중복 타입 정의**

```typescript

/**
 * 표준 API 응답 타입
 */
export interface ApiResponse<T> {
  success: boolean;
  data: T;
  message?: string;
  error?: string;
}

/**
 * 페이지네이션 응답 타입
 */
export interface PaginatedResponse<T> {
  success: boolean;
  data: {
    items: T[];
    total: number;
    page: number;
    limit: number;
    hasMore: boolean;
  };
}

/**
 * 사용 예시
 */
// users API
interface GetUsersData {
  users: User[];
  total: number;
}
const response = await apiClient.get<ApiResponse<GetUsersData>>('/api/users');
const users = response.data.users; // 타입 안전!
```

## 🚨 **자주 발생하는 오류와 해결책**

### 1. Property does not exist on type

```typescript
// ❌ 문제
const tier = user.membershipTier; // Property 'membershipTier' does not exist

// ✅ 해결: 인터페이스에 속성 추가
interface User {
  // ...
  membershipTier?: string;
}
```

### 2. Type 'unknown' has no properties

```typescript
// ❌ 문제
const users = response.data.users; // Property 'users' does not exist on type 'unknown'

// ✅ 해결: API 응답 타입 정의
interface UsersResponse {
  users: User[];
}
const response = await apiClient.get<UsersResponse>('/api/users');
```

### 3. Two different types with this name exist

```typescript
// ❌ 문제: 같은 이름의 타입이 여러 파일에
// file1.tsx: interface Course { ... }
// file2.tsx: interface Course { ... }

// ✅ 해결: 중앙 집중화
// types/course.ts
export interface Course { ... }

// file1.tsx, file2.tsx
import { Course } from '@/types/course';
```

### 4. Argument type mismatch

```typescript
// ❌ 문제
function process(id: string) { ... }
process(123); // Type 'number' is not assignable to type 'string'

// ✅ 해결1: 올바른 타입 전달
process(user.id); // user.id는 string

// ✅ 해결2: 타입 확장 (필요 시)
function process(id: string | number) {
  const stringId = String(id);
  // ...
}
```

### 5. Date vs string 타입 불일치

```typescript
// ❌ 문제
interface Program {
  createdAt: string;
}
program.createdAt = new Date(); // Type 'Date' is not assignable to type 'string'

// ✅ 해결: Date를 string으로 변환
program.createdAt = new Date().toISOString();
```

## 🎓 **실전 예제: 387개 → 41개 해결 과정**

### 대표 사례 1: SavedProgram 확장 (58개 해결!)

**문제:**
```typescript
// 초기 타입 (간단)
interface SavedProgram {
  id: string;
  name: string;
  createdAt: string;
}

// 실제 코드 (58개 속성 사용!)
program.sessionDuration = 60; // ❌ Property does not exist!
program.mainStrokes = ['FR', 'BK']; // ❌ Property does not exist!
// ... 56개 더...
```

**해결:**
```typescript
// 확장된 타입 (58개 속성 모두 정의)
export interface SavedProgram {
  id: string;
  name: string;
  createdAt: string;
  
  // params 확장
  params: {
    startDate: string;
```
