# 🔍 자동 점검 시스템 사용 가이드

## 📋 개요

프로젝트에서 발생할 수 있는 **모든 종류의 문제를 미리 감지하고 자동으로 해결**하는 종합 시스템입니다.

### ✨ 주요 기능

1. **모델 일관성 검사**
   - 모델 파일 존재 여부
   - server/src/index.ts에서 import 여부
   - 스키마 정의 완성도
   - 데이터베이스 컬렉션 생성 확인

2. **라우트 등록 검사**
   - 라우트 파일 존재 확인
   - import 및 app.use 등록 확인
   - 라우트-모델 의존성 검증

3. **환경변수 검사**
   - 필수 환경변수 설정 확인
   - JWT 보안 키 강도 검증

4. **클라이언트-서버 연동 검사**
   - API 호출 경로와 실제 라우트 일치 확인
   - 인터페이스 타입 일치 여부

5. **의존성 검사**
   - 필수 패키지 설치 확인
   - 버전 충돌 감지

6. **TypeScript 검사**
   - tsconfig.json 유효성
   - 컴파일 가능 여부

## 🚀 사용 방법

### 1. 전체 헬스 체크 실행

```bash
npm run check-health
```

**이 명령어는:**
- 프로젝트의 모든 측면을 점검합니다
- 문제를 발견하면 상세한 해결 방법을 제시합니다
- `health-check-report.json`에 결과를 저장합니다
- `DEVELOPMENT.md`에 자동으로 결과를 추가합니다

**출력 예시:**
```
🔍 JJ Swim Lab 종합 헬스 체크

━━━ 모델 일관성 검사 ━━━

ℹ️  총 25개 모델 파일 발견
✅ User - Import 확인됨
✅ Center - Import 확인됨
❌ CenterInfo 모델이 index.ts에서 import되지 않음
ℹ️  해결: server/src/index.ts에 "import './models/CenterInfo';" 추가 필요

━━━ 종합 검사 결과 ━━━

총 검사 항목: 87
통과: 82
실패: 3
경고: 2

━━━ 발견된 오류 ━━━

❌ 1. CenterInfo 모델이 index.ts에서 import되지 않음
ℹ️  해결: server/src/index.ts에 "import './models/CenterInfo';" 추가 필요

❌ 2. center-info 라우트가 등록되지 않음
ℹ️  해결: server/src/index.ts에 "app.use('/api/center-info', centerInfoRoutes);" 추가

⚠️  3개의 문제가 발견되었습니다. 수정 후 다시 실행하세요.
```

### 2. 자동 수정 실행 (미리보기)

```bash
npm run fix-issues:dry
```

**이 명령어는:**
- 실제로 파일을 수정하지 **않고**
- 어떤 내용이 수정될지 미리 보여줍니다

**출력 예시:**
```
🔧 JJ Swim Lab 자동 문제 해결

ℹ️  DRY-RUN 모드: 실제로 파일을 수정하지 않고 미리보기만 표시합니다.

━━━ 누락된 모델 Import 자동 추가 ━━━

ℹ️  [DRY-RUN] 3개 모델 import 추가 예정: CenterInfo, CenterLevel, StudentLevel

━━━ 누락된 라우트 Import 및 등록 자동 추가 ━━━

ℹ️  [DRY-RUN] 2개 라우트 import 추가 예정
ℹ️  [DRY-RUN] 2개 라우트 등록 추가 예정
```

### 3. 자동 수정 실행 (실제 적용)

```bash
npm run fix-issues
```

**이 명령어는:**
- 발견된 문제를 **실제로 수정**합니다
- 수정 전 자동으로 백업을 생성합니다
- 수정 내용을 `auto-fix-report.json`에 저장합니다

**출력 예시:**
```
🔧 JJ Swim Lab 자동 문제 해결

━━━ 누락된 모델 Import 자동 추가 ━━━

ℹ️  백업 생성: backups/auto-fix-1234567890/server/src/index.ts
✅ 3개 모델 import 추가됨: CenterInfo, CenterLevel, StudentLevel
✅ 모델 등록 확인 섹션에도 추가됨

━━━ 자동 수정 완료 ━━━

총 3개 항목이 수정되었습니다.

수정된 내용:
1. [model-import] server/src/index.ts
   - 모델: CenterInfo, CenterLevel, StudentLevel

✅ 백업 위치: backups/auto-fix-1234567890
ℹ️  문제가 발생하면 백업에서 복원할 수 있습니다.

✨ 자동 수정 완료!

다음 명령어로 검증하세요:
  npm run check-health
```

### 4. 개발 서버 시작 (자동 체크 포함)

```bash
npm run dev
```

**이 명령어는:**
- 개발 서버 시작 **전에** 자동으로 헬스 체크를 실행합니다
- 문제가 발견되면 서버 시작을 차단합니다
- 모든 검사를 통과해야만 서버가 시작됩니다

**체크를 건너뛰고 서버만 시작:**
```bash
npm run dev:skip-check
```

## 📊 점검 항목 상세

### 1. 모델 일관성 검사

#### 검사 내용:
- ✅ `server/src/models/` 디렉토리의 모든 `.ts` 파일
- ✅ 각 모델이 `server/src/index.ts`에서 import되었는지
- ✅ `mongoose.model()` export 구문 존재
- ✅ 스키마 정의의 중괄호 일치 여부
- ✅ TypeScript 인터페이스와 스키마 일치

#### 발견되는 문제:
- ❌ 모델 파일은 있지만 import 안됨 (예: CenterInfo)
- ❌ export 구문 누락
- ❌ 스키마 문법 오류 (괄호 불일치)

#### 자동 수정:
- ✅ 누락된 모델 import 자동 추가
- ✅ 모델 등록 확인 코드 자동 생성

### 2. 라우트 등록 검사

#### 검사 내용:
- ✅ `server/src/routes/` 디렉토리의 모든 `.ts` 파일
- ✅ 각 라우트가 import되었는지
- ✅ `app.use('/api/...', ...Routes)` 등록 확인
- ✅ 라우트에서 사용하는 모델이 실제 존재하는지

#### 발견되는 문제:
- ❌ 라우트 파일은 있지만 import 안됨
- ❌ import는 되었지만 app.use 등록 안됨
- ❌ 존재하지 않는 모델을 import하려고 함

#### 자동 수정:
- ✅ 누락된 라우트 import 자동 추가
- ✅ app.use 등록 자동 추가

### 3. 환경변수 검사

#### 검사 내용:
- ✅ `.env` 파일 존재 여부
- ✅ 필수 환경변수 설정 확인
  - `MONGODB_URI`
  - `JWT_SECRET`
  - `PORT`
  - `NODE_ENV`
- ✅ JWT_SECRET 보안 강도 (32자 이상)

#### 발견되는 문제:
- ❌ .env 파일이 없음
- ❌ 필수 환경변수 누락
- ⚠️ JWT_SECRET이 너무 짧음 (보안 취약)

#### 자동 수정:
- ✅ .env 템플릿 자동 생성
- ✅ 안전한 JWT_SECRET 자동 생성

### 4. 클라이언트-서버 연동 검사

#### 검사 내용:
- ✅ 클라이언트에서 호출하는 모든 API 경로 추출
- ✅ 각 API 경로에 대응하는 서버 라우트 존재 확인
- ✅ 인터페이스 타입 일치 여부

#### 발견되는 문제:
- ⚠️ 클라이언트에서 `/api/center-info` 호출하지만 서버에 라우트 없음
- ⚠️ 응답 타입이 클라이언트 인터페이스와 다름

### 5. 의존성 검사

#### 검사 내용:
- ✅ 서버 필수 패키지: `express`, `mongoose`, `jsonwebtoken`, `bcryptjs`, `cors`, `dotenv`
- ✅ 클라이언트 필수 패키지: `react`, `react-dom`, `next`
- ✅ package.json 파싱 가능 여부

#### 발견되는 문제:
- ❌ 필수 패키지 누락
- ⚠️ 버전 충돌 가능성

### 6. TypeScript 검사

#### 검사 내용:
- ✅ `tsconfig.json` 파일 존재
- ✅ JSON 파싱 가능 여부
- ✅ 필수 설정 확인

## 🎯 실전 사용 시나리오

### 시나리오 1: 새로운 모델을 만들었는데 API가 404 에러

**문제:**
```typescript
// server/src/models/CenterInfo.ts 생성
export const CenterInfo = mongoose.model<ICenterInfo>('CenterInfo', CenterInfoSchema);
```

**증상:**
```
GET /api/center-info → 404 Not Found
```

**해결:**
```bash
# 1. 문제 확인
npm run check-health

# 출력:
# ❌ CenterInfo 모델이 index.ts에서 import되지 않음
# ℹ️  해결: server/src/index.ts에 "import './models/CenterInfo';" 추가 필요

# 2. 자동 수정 (미리보기)
npm run fix-issues:dry

# 3. 자동 수정 (실제 적용)
npm run fix-issues

# 4. 검증
npm run check-health
# ✅ 모든 검사 통과!
```

### 시나리오 2: 라우트는 만들었는데 서버에서 인식 안됨

**문제:**
```typescript
// server/src/routes/center-management.ts 생성
router.get('/', async (req, res) => { ... });
export default router;
```

**증상:**
```
서버 로그에 해당 라우트 관련 메시지 없음
```

**해결:**
```bash
npm run check-health

# 출력:
# ❌ center-management 라우트가 import되지 않음
# ❌ center-management 라우트가 등록되지 않음

npm run fix-issues
# ✅ import 및 app.use 자동 추가됨
```

### 시나리오 3: 팀원이 잘못된 코드를 커밋하려고 할 때

**Git Hook 설정:**
```bash

  echo "❌ 헬스 체크 실패! 커밋이 차단되었습니다."
  echo "문제를 수정하거나 'npm run fix-issues'로 자동 수정하세요."
  exit 1
fi
```

**결과:**

- 팀 전체의 코드 품질 유지

## ❓ FAQ

### Q: 자동 수정이 안전한가요?
**A:** 네, 모든 수정 전에 자동으로 백업을 생성합니다. `backups/` 디렉토리에서 언제든지 복원할 수 있습니다.

### Q: 개발 서버 시작할 때마다 체크하면 느리지 않나요?
**A:** 일반적으로 1-3초 이내에 완료됩니다. 급할 때는 `npm run dev:skip-check`를 사용하세요.

### Q: 팀원들에게 강제로 적용하려면?
**A:** Git pre-commit hook을 설정하면 됩니다. 문제가 있으면 커밋이 차단됩니다.

### Q: CenterInfo 외에 다른 모델도 자동으로 찾아주나요?
**A:** 네! `server/src/models/` 디렉토리의 모든 모델을 자동으로 스캔하고 검사합니다.

### Q: 클라이언트 컴포넌트도 검사하나요?
**A:** 현재는 API 호출 경로만 검사합니다. 향후 업데이트에서 컴포넌트 import 등도 추가될 예정입니다.
