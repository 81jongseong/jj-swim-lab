# 📝 JJ Swim Lab 개발 주석 가이드

## 🎯 목적

이 가이드는 **파일 내 주석을 통한 명확한 의존성과 기능 정의**를 통해 개발 시 혼란을 방지하고, 코드의 가독성과 유지보수성을 높이는 것을 목표로 합니다.

## 📋 주석 구조

### 1. **파일 헤더 주석 구조**

```typescript
/**
 * 🏢 파일명 - 간단한 설명
 *
 * =============================================================================
 * 📋 **의존성 파일들**
 * =============================================================================
 * 🔗 **직접 의존성**:
 *   - ../models/ModelName.ts (모델 설명)
 *   - ../middleware/auth.ts (미들웨어 설명)
 * 
 * 🔗 **연동되는 클라이언트 파일들**:
 *   - client/app/path/page.tsx (페이지 설명)
 * 
 * 🔗 **데이터베이스 연동**:
 *   - CollectionName 컬렉션 (데이터 설명)
 *
 * =============================================================================
 * 🔄 **현재 구현된 기능들**
 * =============================================================================
 * ✅ **완전 구현**:
 *   - 기능 1 (상태)
 *   - 기능 2 (상태)
 * 
 * ✅ **부분 구현**:
 *   - 기능 3 (부분 구현 상태)
 * 
 * ❌ **미구현**:
 *   - 기능 4 (미구현 이유)
 *
 * =============================================================================
 * ⚠️ **중요한 주의사항**
 * =============================================================================
 * 🚨 **주의사항 1**: 설명
 * 🚨 **주의사항 2**: 설명
 */
```

### 2. **환경 변수 주석 구조**

```bash
# =============================================================================
# 🔗 섹션명
# =============================================================================
# 📋 **의존성**: 
#   - 파일명 (역할 설명)
#   - 패키지명 (용도 설명)
# 🔄 **기능**: 
#   - 기능 1 설명
#   - 기능 2 설명
# ⚠️ **주의사항**: 
#   - 주의사항 1
#   - 주의사항 2
VARIABLE_NAME=value
```

## 🔧 적용 방법

### 1. **새 파일 생성 시**

1. 파일 생성 전 기존 파일들과의 의존성 확인
2. 위의 주석 구조를 따라 파일 헤더 작성
3. 모든 의존성 파일 경로 명시
4. 구현 상태를 명확히 구분 (✅완전구현, ✅부분구현, ❌미구현)

### 2. **기존 파일 수정 시**

1. 파일 헤더의 의존성 정보 업데이트
2. 변경된 기능의 상태 업데이트
3. 새로운 주의사항 추가
4. 개발 히스토리 업데이트

### 3. **환경 변수 추가 시**

1. 해당 섹션에 주석 구조 추가
2. 의존성, 기능, 주의사항 명시
3. 현재 구현 상태 표시

## 📊 상태 표시 기호

- ✅ **완전 구현**: 기능이 완전히 작동함
- ✅ **부분 구현**: 기본 기능은 작동하지만 일부 기능 미완성
- ❌ **미구현**: 아직 구현되지 않음
- 🚨 **중요**: 반드시 주의해야 할 사항
- 🔗 **의존성**: 다른 파일이나 시스템과의 연결
- 🔄 **기능**: 해당 코드의 역할과 기능

## 🎯 장점

### 1. **개발 효율성 향상**
- 파일 간 의존성을 한눈에 파악 가능
- 어떤 기능이 구현되었는지 명확히 알 수 있음
- 수정 시 영향 범위를 쉽게 파악 가능

### 2. **오류 방지**
- 존재하지 않는 파일 참조 방지
- 중복 기능 구현 방지
- 타입 불일치 문제 사전 방지

### 3. **유지보수성 향상**
- 코드의 목적과 역할을 명확히 이해 가능
- 새로운 개발자가 빠르게 코드베이스 파악 가능
- 리팩토링 시 안전한 변경 가능

## 📝 예시

### 환경 변수 파일 (env.example)
```bash
# =============================================================================
# 🔐 JWT CONFIGURATION
# =============================================================================
# 📋 **의존성**: 
#   - middleware/auth.ts (인증 미들웨어)
#   - routes/auth.ts (로그인/로그아웃 API)
#   - 클라이언트 useAuth.tsx (인증 상태 관리)
# 🔄 **기능**: 
#   - 사용자 인증 토큰 생성 및 검증
#   - 로그인 상태 유지
#   - API 접근 권한 제어
# ⚠️ **주의사항**: 
#   - JWT_SECRET은 반드시 강력한 비밀키 사용
#   - 프로덕션에서는 환경변수로 보호
JWT_SECRET=your-super-secret-jwt-key-here
JWT_EXPIRES_IN=7d
```

### API 라우트 파일
```typescript
/**
 * 🏢 JJ Swim Lab - 센터 정보 관리 API
 *
 * =============================================================================
 * 📋 **의존성 파일들**
 * =============================================================================
 * 🔗 **직접 의존성**:
 *   - ../models/Center.ts (센터 데이터 모델)
 *   - ../models/User.ts (사용자 데이터 모델)
 *   - ../middleware/auth.ts (인증 미들웨어)
 * 
 * 🔗 **연동되는 클라이언트 파일들**:
 *   - client/app/center-admin/info/page.tsx (센터 정보 관리 페이지)
 * 
 * =============================================================================
 * 🔄 **현재 구현된 기능들**
 * =============================================================================
 * ✅ **완전 구현**:
 *   - GET /api/center-info (센터 정보 조회)
 *   - PUT /api/center-info (센터 정보 수정)
 * 
 * ❌ **미구현**:
 *   - 실제 이미지 파일 시스템 연동
 * 
 * =============================================================================
 * ⚠️ **중요한 주의사항**
 * =============================================================================
 * 🚨 **권한 체크**: centerAdmin, superAdmin만 접근 가능
 * 🚨 **데이터 검증**: Center 모델 스키마와 일치해야 함
 */
```
